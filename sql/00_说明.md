# SQL 目录说明

这里的脚本按执行顺序编号，对应「电商用户行为漏斗与转化分析」的完整分析过程。
全部在 DataGrip 里针对 MySQL 8.0 执行。

| 顺序 | 文件 | 作用 | 产出 |
| --- | --- | --- | --- |
| 01 | `01_create_table.sql` | 建库建表 | `ecommerce.events` |
| 02 | `02_load_data.sql` | 导入天池原始数据 | 12,256,906 行 |
| 03 | `03_overview.sql` | 数据体检 | 规模、行为分布、每日活跃 |
| 04 | `04_funnel.sql` | 整体漏斗（含口径改造对照） | 全链路转化率 2.11% |
| 05 | `05_category.sql` | 品类拆解 | 大品类转化率仅长尾一半 |
| 06 | `06_time_gap.sql` | 决策时间窗 | 76.5% 的购买在 24 小时内 |
| 07 | `07_promo_vs_normal.sql` | 大促 vs 平日 | 大促转化率 1.72 倍 |
| 08 | `08_promo_trend.sql` | 大促前后日趋势 | 12-11 蓄水、之后无回落 |
| 09 | `09_repurchase.sql` | 复购分布 | 87.2% 的用户多天购买 |

## 执行前要确认的两件事

**一、数据源勾选了本地导入。** DataGrip 里打开数据源属性，在 **Advanced** 标签加一项
`allowLoadLocalInfile` = `true`（有些版本在 **Options** 标签里叫 "Allow LOAD DATA LOCAL INFILE"）。
不勾的话执行 02 会报 `Loading local data is disabled`。

**二、原始数据路径。** 02 里写的是
`F:/数分项目/tianchi_mobile_recommend_train_user/tianchi_mobile_recommend_train_user.csv`，
如果你换了解压位置，改这一行即可。

## 几个口径提醒

**漏斗用的是「用户-商品对」粒度，不是用户级。** 原因写在 04 的注释里：这份数据人均行为
1,226 条，用户级漏斗算出来 88.86% 的用户都购买过，指标饱和、没有区分度。

**时间字段只精确到小时。** 所以"浏览后多久购买"的最小单位是小时，
"同一小时内"这一档包含了当天看当天买的所有情况。

**`buy` 是独立事件。** 购买不一定有加购记录，浏览、加购、购买三层不是严格嵌套关系。

**品类只有 ID 没有名称。** 报告里无法指名具体商品，只能以 ID 指代。
